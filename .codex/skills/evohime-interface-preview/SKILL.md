# Визуальный preview интерфейса EvoHime

Используй этот skill, когда нужно увидеть, как действительно выглядит часть
интерфейса EvoHime в текущем checkout. Результатом является снимок живого
собранного target и короткий визуальный разбор, а не пересказ JSX или CSS.

## Обязательное правило свежести

Перед каждым новым снимком сначала определи UI-target и пересобери его из
текущих исходников. Нельзя показывать старый `out/`, старый package или ранее
снятый скриншот как актуальный результат.

Рабочая директория сборки — `desktop/evohime-electron`:

- standalone updater, `updater.html`, `UpdaterApp` и updater window:
  `npm run build:updater`;
- shell, `index.html`, startup/update gate, workbench, панели, модальные окна и
  прочие renderer-поверхности shell: `npm run build:shell`.

Если зависимости Electron отсутствуют, сначала проверь проектный способ
bootstrap и существующий `node_modules`; не добавляй новую зависимость и не
подменяй сборку ручным HTML. Если сборка завершилась ошибкой, остановись:
снимок не считается актуальным и нельзя говорить, что внешний вид проверен.

## Поиск поверхности

Сначала найди реальную точку входа по исходникам и прочитай её вместе с
связанными стилями, main/preload wiring и тестом, если он есть. Используй
`rg`, а не догадки по имени компонента.

Выбери target по этой карте:

| Запрос | Исходная поверхность | Target |
| --- | --- | --- |
| updater, окно обновления | `src/renderer/updater.html`, `UpdaterApp.tsx`, `UpdaterSurface.css`, `src/main/updater-window.ts` | `updater` |
| обычное окно, gate, Workbench, любая renderer-панель | `src/renderer/index.html`, соответствующий React-компонент и `styles.css`/локальный CSS | `shell` |
| overlay, tray или native dialog | вызывающий main-файл и связанная renderer-поверхность | `shell`, затем открыть реальный trigger |

`.codex/updater-window-preview.html` и `docs/update-window-design.md` можно
использовать только как design reference. Они не доказывают внешний вид
текущего React/Electron UI.

## Запуск собранного target

После успешной сборки запускай preview из `desktop/evohime-electron` через
существующий `npm run start` (`electron-vite preview`). Перед запуском передай
`EVOHIME_ELECTRON_TARGET=updater` для updater или `shell` для обычной оболочки,
чтобы preview открыл именно тот output, который только что собран.

Для поверхности, зависящей от данных, используй только существующие dev,
fixture или test seams. Не выполняй реальное применение обновления, не меняй
установленный EvoHime и не используй production state ради красивого кадра.
Если состояние нельзя получить без внешнего сервиса или необратимого действия,
сними ближайшее безопасное состояние и явно отметь, что состояние не было
воспроизведено.

Если обычный shell требует native runtime, это не отменяет пересборку UI. Сначала
проверь, что renderer действительно загрузился; затем либо используй имеющийся
dev package/native binaries, либо честно сообщи, какая часть экрана недоступна.
Не маскируй ошибку заглушкой и не называй статический макет runtime-снимком.

## Съёмка и просмотр

Для управления Windows и Electron используй `computer-use` skill и его
`@oai/sky` API из persistent `node_repl` (`mcp__node_repl__js`). Не используй
`mcp__cua_repl` для нативных окон: он может показывать только браузерные
поверхности, а не список окон Windows.

Перед первой автоматизацией в свежей `node_repl` сессии прочитай
`computer-use/SKILL.md` и обязательные `docs/guidance.md` и
`docs/confirmations.md` из установленного пакета этого skill. Инициализируй
`sky` ровно по инструкции skill. Затем:

1. Вызови `sky.list_apps()` и найди приложение с живым окном preview.
   Preview может быть зарегистрирован как `Electron` с окном из текущего
   `desktop/evohime-electron/node_modules/electron/dist/electron.exe`, а не как
   установленное приложение EvoHime.
2. Выбери окно по данным, возвращённым `list_apps()` или `list_windows()`.
   Если подходящих окон несколько, уточни по заголовку и требуй ровно одно;
   не конструируй идентификаторы окна самостоятельно.
3. Получи объект окна через `sky.get_window({ id, app })`, активируй его и сними
   `sky.get_window_state({ window, include_screenshot: true, include_text: true })`.
   Ответ автоматически показывает живой снимок; рассматривай именно его.

Дождись загрузки окна после сборки, выбери окно EvoHime/EvoHimeUpdater и сними:

1. всё окно для общей композиции;
2. нужную область или состояние после прокрутки/открытия trigger, если
   пользователь просит конкретную часть интерфейса;
3. отдельный кадр каждого важного состояния, если запрос касается состояний.

Скриншот должен быть получен из живого окна. Если `@oai/sky` недоступен,
`node_repl` не может импортировать пакет или окно не отображается в его
инвентаре, не заявляй, что интерфейс просмотрен: верни только найденные
source/build facts и укажи, что визуальное доказательство отсутствует.

Не сохраняй и не декодируй payload снимка отдельно: используй изображение,
которое `get_window_state` отображает в ответе. Сохраняй файл снимка только
если пользователь прямо просит файл на диске; по умолчанию результат показывай
в ответе. Не смешивай `@oai/sky` с другими Windows UI automation API в рамках
одной задачи.

После снимка проверь глазами:

- фактические размеры окна, отступы, выравнивание и clipping/overflow;
- текст, переносы, иконки, контраст, hover/focus и системные кнопки;
- соответствие активному состоянию и данным, а не только happy path;
- отсутствие пустых областей, старого layout, видимого терминала и ошибок в
  загрузке renderer.

Если вид отличается от design reference, источником истины для текущего
поведения являются собранные исходники и runtime-снимок; reference нужно
указать только как обнаруженное расхождение.

## Завершение

Закрой preview и управляемые окна после съёмки, останови только запущенный для
этой проверки процесс и не удаляй чужие build outputs или пользовательские
изменения. Снимки не сохраняй в Git без отдельного запроса.

В результате сообщи:

- какую поверхность и source paths проверял;
- какой target и build command выполнил, с результатом;
- какое runtime-состояние было видно;
- что видно на снимке и есть ли найденные визуальные проблемы;
- какие состояния или зависимости не удалось безопасно воспроизвести.

Не говори «выглядит актуально», если target не пересобран непосредственно
перед этим снимком.
