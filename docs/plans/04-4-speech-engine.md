# Этап 04.4: Движок распознавания

Этап плана [04 Постоянное слушание и ambient-память](04-0-ambient-listening.md).

## Зависимости

Блокирующие: этап 04.3 — движок получает готовые высказывания от сегментатора;
этап 04.2 — распознанное надо куда-то положить.

Разблокирует: 04.5–04.7.

## Что этап отдаёт наружу

Локальное распознавание речи whisper.cpp с честными состояниями доступности и
дедупликацией; транскрипты доходят до хранилища.

## Что уже есть в коде

Только `FixtureEngine` и `NullEngine` из 04.3. Ни DLL, ни модели, ни резолвера
каталога инструментов. Переменных `EVOHIME_LISTENER_TOOLS_DIR` и
`EVOHIME_TOOLS_DIR` в коде тоже нет — обе вводятся этим этапом.

Сверено с кодом, потому что на этом стоит вся поставка рантайма:

- образец загрузчика — `desktop/evohime-electron/src/main/update/release-installer.ts`.
  Он ходит **в GitHub Releases API** (`githubApiBase(repositoryUrl)`, релиз по
  тегу `installer`), берёт URL ассета из JSON релиза и сверяет SHA-256 с
  манифестом (`:108`). Это не «pinned URL к CDN»: доверие даёт релизный канал
  GitHub плюс хеш из манифеста. Там же — готовые границы, которые надо
  повторить: `MAX_MANIFEST_BYTES`, `MAX_INSTALLER_BYTES`, `REQUEST_TIMEOUT_MS`;
- **проверки Authenticode в репозитории нет ни в одном виде**, и это не
  случайный пропуск: проект вообще ничего не подписывает. В
  `.github/workflows/windows.yml` нет `signtool` и сертификата, в
  `electron-builder.yml` нет ни `certificateFile`, ни `sign`, а `publish: null`.
  Значит собственный `whisper.dll` подписи иметь не будет;
- `EXTERNAL_URL_ALLOW_LIST` (`security-policy.ts:30`) ограничивает только
  ссылки, открываемые наружу из shell, но задаёт тон: новый внешний хост —
  это новый корень доверия, и заводить его без нужды не стоит.

## Содержание

- `WhisperDllEngine`: `libloading` и собственные FFI-биндинги на C API
  whisper.cpp (`whisper_init_from_file_with_params`, `whisper_full`,
  `whisper_full_n_segments`, `whisper_full_get_segment_text`, `whisper_free` и
  ещё несколько). CMake на этапе `cargo build` не нужен — это условие
  работоспособности self-update, который ставит только Git, Node, Rustup и MSVC
  Build Tools.
- Модель по умолчанию — `ggml-small-q5_1` (~490 МБ): она обычно точнее `base`
  для русской речи, а при коротких высказываниях через VAD нагрузка приемлема.
- Резолвер каталога инструментов по порядку: `EVOHIME_LISTENER_TOOLS_DIR` →
  `EVOHIME_TOOLS_DIR` → `%LOCALAPPDATA%\EvoHime\tools\listener`. Хардкод
  путей рабочих checkout запрещён. Первый существующий каталог с валидным
  манифестом побеждает; недоступный каталог — переход к следующему кандидату,
  а не ошибка.

```
<tools>\listener-runtime.json     манифест: версии, имена файлов, sha256, ABI
<tools>\whisper.dll
<tools>\onnxruntime.dll           опционально; нет — энергетический VAD + уведомление
<tools>\silero_vad.onnx           опционально; отсутствие явно видно в UI
<tools>\models\ggml-small-q5_1.bin
```

- **Что именно является корнем доверия.** Основной механизм — SHA-256 каждого
  файла из манифеста, полученного тем же релизным каналом GitHub, что и сам
  установщик продукта. Несовпадение хеша или ABI — `EngineUnavailable` с кодом,
  а не загрузка. DLL загружается только из выбранного каталога tools; тест
  проверяет отсутствие попыток открыть DLL/модель по пути вне этого каталога.
- **Authenticode — дополнительная проверка, а не основная, и её граница
  названа явно.** Проверять подпись имеет смысл ровно у тех файлов, у которых
  она есть: `onnxruntime.dll` подписан Microsoft, и для него несовпадение или
  отсутствие подписи — отказ. Собственный `whisper.dll` подписан не будет,
  пока в проекте не появится настоящий signing pipeline (сертификат в CI и
  `signtool`/electron-builder), — поэтому требовать подпись у своих артефактов
  сейчас нельзя: такое требование не выполнил бы и сам продукт. Механизм
  проверки, когда она применима, называется явно
  (`Get-AuthenticodeSignature` через pwsh либо нативный `WinVerifyTrust`).
  Введение code-signing — отдельная работа за пределами плана 04; до неё
  манифест плюс релизный канал остаются единственным корнем доверия, и это
  записывается в `docs/architecture.md` без приукрашивания.
- Поставка: `whisper.dll`, `onnxruntime.dll`, `silero_vad.onnx` и модели
  выкладываются отдельным релизным ассетом с манифестом — тем же механизмом,
  что `release-installer.ts`, а не через новый хост. Скачивает Electron main
  (TLS, размерные потолки, таймаут, SHA-256, ABI); агент и Core не скачивают
  ничего. Обновление проверяется при запуске и предлагается пользователю, а не
  применяется незаметно.
- Загрузка идёт во временный staging-каталог с атомарным rename манифеста.
  Неудачные попытки имеют ограниченный backoff и видимое уведомление; старый
  рабочий набор сохраняется, ручная загрузка доступна из UI. Неиспользуемые
  версии удаляются только после успешного переключения и проверки отсутствия
  активных mmap.
- Дедупликация: `text_hash` (NFKC, lowercase, без пунктуации) в окне 60 с плюс
  near-dup по token-set ratio ≥ 0.9 против пяти предыдущих высказываний.
  Подавленное считается счётчиком, а не пишется.
- Бюджет: измерение RTF; RTF > 0.5 на пяти высказываниях подряд переключает
  модель на следующую меньшую в лестнице `small → base → tiny`. После `tiny`
  листенер переходит в `PausedByPolicy` с причиной `engine_degraded`; каждая
  смена модели публикует `ambient.engine` и уведомляет UI. Улучшение нагрузки
  не переключает модель обратно автоматически в той же сессии.
- Модель открывается read-only mmap; параметры `whisper_full` фиксированы и не
  содержат путей вывода.
- Опциональная cargo-feature `whisper-static` (`whisper-rs`) для dev-сборок;
  в packaging не участвует (она как раз тянет CMake).

## Проверки

- отсутствие DLL или модели даёт `engine_unavailable`, а не тишину и не панику;
- битый или подменённый файл по SHA-256 не загружается;
- `onnxruntime.dll` без валидной подписи Microsoft отвергается; отсутствие
  подписи у собственного `whisper.dll` **не** является отказом, и это
  зафиксировано отдельным тестом, чтобы поведение не считалось недосмотром;
- дедупликация подавляет повтор и считает его счётчиком;
- деградация по RTF срабатывает и переключает модель вниз по лестнице;
- `EVOHIME_LISTENER_ENGINE_E2E=1` прогоняет реальный движок на фикстурах; без
  переменной используется `FixtureEngine`, и CI зелёный без DLL и модели. Приём
  тот же, что у `EVOHIME_UPDATE_E2E` в
  `desktop/evohime-electron/tests/e2e/source-update.e2e.test.ts:31`, но
  реализуется на стороне Rust: тест помечается `#[ignore]`-эквивалентом через
  ранний выход по отсутствию переменной.

## Критерии готовности

- транскрипты появляются в хранилище и видны через IPC;
- отсутствие движка — честное состояние, а не маскировка;
- ни один шаг сборки продукта не требует CMake;
- граница доверия к поставляемому рантайму описана честно: хеш из манифеста
  релизного канала, а не подпись, которой у продукта пока нет.
