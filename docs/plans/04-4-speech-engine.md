# Этап 04.4: Движок распознавания

Этап плана [04 Постоянное слушание и ambient-память](04-0-ambient-listening.md).

## Зависимости

Блокирующие: этап 04.3 — движок получает готовые высказывания от сегментатора;
этап 04.2 — распознанное надо куда-то положить.

Разблокирует: 04.5–04.7.

## Что этап отдаёт наружу

Локальное распознавание речи whisper.cpp с честными состояниями доступности и
дедупликацией; транскрипты доходят до хранилища.

## Что уже есть в коде

Только `FixtureEngine` и `NullEngine` из 04.3. Ни DLL, ни модели, ни резолвера
каталога инструментов.

## Содержание

- `WhisperDllEngine`: `libloading` и собственные FFI-биндинги на C API
  whisper.cpp (`whisper_init_from_file_with_params`, `whisper_full`,
  `whisper_full_n_segments`, `whisper_full_get_segment_text`, `whisper_free` и
  ещё несколько). CMake на этапе `cargo build` не нужен — это условие
  работоспособности self-update, который ставит только Git, Node, Rustup и MSVC
  Build Tools.
- Модель по умолчанию — `ggml-small-q5_1` (~490 МБ): она обычно точнее `base`
  для русской речи, а при коротких высказываниях через VAD нагрузка приемлема.
- Резолвер каталога инструментов по порядку: `EVOHIME_LISTENER_TOOLS_DIR` →
  `EVOHIME_TOOLS_DIR` → `%LOCALAPPDATA%\EvoHime\tools\listener`. Хардкод
  путей рабочих checkout запрещён. Первый существующий каталог с валидным
  манифестом побеждает; недоступный каталог — переход к следующему кандидату,
  а не ошибка.

```
<tools>\listener-runtime.json     манифест: версии, имена файлов, sha256, ABI
<tools>\whisper.dll
<tools>\onnxruntime.dll           опционально; нет — энергетический VAD + уведомление
<tools>\silero_vad.onnx           опционально; отсутствие явно видно в UI
<tools>\models\ggml-small-q5_1.bin
```

- Несовпадение SHA-256, ABI или Authenticode-подписи — `EngineUnavailable` с
  кодом, а не загрузка. DLL загружается только из выбранного каталога tools;
  тест проверяет отсутствие попыток открыть DLL/модель по пути вне этого
  каталога.
- `whisper.dll`, `onnxruntime.dll`, `silero_vad.onnx` и модели поставляются
  одним подписанным манифестом через контролируемый EvoHime CDN/релиз. Electron
  main скачивает их по pinned URL с проверкой TLS, подписи, SHA-256 и ABI;
  агент и Core ничего не скачивают. Обновление проверяется при запуске и
  предлагается пользователю, а не применяется незаметно.
- Загрузка идёт во временный staging-каталог с атомарным rename манифеста.
  Неудачные попытки имеют ограниченный backoff и видимое уведомление; старый
  рабочий набор сохраняется, ручная загрузка доступна из UI. Неиспользуемые
  версии удаляются только после успешного переключения и проверки отсутствия
  активных mmap.
- Дедупликация: `text_hash` (NFKC, lowercase, без пунктуации) в окне 60 с плюс
  near-dup по token-set ratio ≥ 0.9 против пяти предыдущих высказываний.
  Подавленное считается счётчиком, а не пишется.
- Бюджет: измерение RTF; RTF > 0.5 на пяти высказываниях подряд переключает
  модель на следующую меньшую в лестнице `small → base → tiny`. После `tiny`
  листенер переходит в `PausedByPolicy` с причиной `engine_degraded`; каждая
  смена модели публикует `ambient.engine` и уведомляет UI. Улучшение нагрузки
  не переключает модель обратно автоматически в той же сессии.
- Модель открывается read-only mmap; параметры `whisper_full` фиксированы и не
  содержат путей вывода.
- Опциональная cargo-feature `whisper-static` (`whisper-rs`) для dev-сборок;
  в packaging не участвует.

## Файлы

- создать: `crates/evohime-listener/src/engine/{mod.rs,whisper_dll.rs,fixture.rs,null.rs}`,
  `crates/evohime-listener/src/tools_dir.rs`;
- изменить: `crates/evohime-listener/Cargo.toml`,
  `crates/evohime-core/src/lib.rs` (приём и запись транскриптов),
  `docs/architecture.md`.

## Проверки

- отсутствие DLL или модели даёт `engine_unavailable`, а не тишину и не панику;
- битый или подменённый файл по SHA-256 не загружается;
- дедупликация подавляет повтор и считает его счётчиком;
- деградация по RTF срабатывает и переключает модель вниз по лестнице;
- `EVOHIME_LISTENER_ENGINE_E2E=1` прогоняет реальный движок на фикстурах; без
  переменной используется `FixtureEngine`, и CI зелёный без DLL и модели. Приём
  тот же, что у `EVOHIME_UPDATE_E2E` в
  `desktop/evohime-electron/tests/e2e/source-update.e2e.test.ts`, но реализуется
  на стороне Rust: тест помечается `#[ignore]`-эквивалентом через ранний выход
  по отсутствию переменной.

## Критерии готовности

- транскрипты появляются в хранилище и видны через IPC;
- отсутствие движка — честное состояние, а не маскировка;
- ни один шаг сборки продукта не требует CMake.
