# План 183.0 — Rust public API documentation

Статус: active implementation contract. Это план качества документации; он не
считает текущее покрытие полным и не меняет runtime-контракты.

## Цель

Сделать внешне доступные Rust API всех workspace crates понятными и проверяемыми:
добавить точные `///` описания и полезные примеры, запускать примеры как
doc-tests и постепенно закрепить полноту через rustdoc gates.

## Текущее основание

Workspace содержит 22 пакета. Поверхностный поиск по Rust исходникам находит
около 6 260 объявлений `pub`; это оценка, не точный перечень внешне достижимых
элементов. Некоторые объявления являются crate-internal re-exports, деталями
реализации, тестовым/сгенерированным кодом или принадлежат бинарным targets.
План должен сначала вычислить фактически достижимый API каждого library target
из его root и публичных re-exports.

Rustdoc генерирует документацию из исходников и `///` комментариев. `#[cfg(doc)]`
не является требованием включения генерации; применять его допустимо только
для конкретных doc-only элементов, нужных для корректной сборки rustdoc.

## Граница

В scope входят все публично достижимые элементы библиотечных targets workspace:
модули и re-exports, типы и их публичные поля, enum variants, функции и методы,
traits и их associated items, константы, type aliases и публичные макросы.
Документация должна пояснять назначение, ограничения, ошибки, владение/потоки,
безопасность и совместимость там, где это влияет на использование.

Не входят внутренние `pub(crate)`/`pub(super)` API, закрытые детали реализации,
массовое переписывание русских комментариев, продуктовая документация вне
затронутых rustdoc entrypoints и изменения runtime/API ради doc coverage.
Generated code документируется на поддерживаемой границе исходника или
re-export, а не ручным редактированием generated artifacts.

## Зависимости

### Блокирующие

- Нет внешних или runtime-планов. Этапы 1–4 этого плана выполняются
  последовательно.

### Опциональные

- Существующие crate README и examples можно использовать, если они актуальны;
  их отсутствие не должно блокировать точечные rustdoc-примеры.

## Критерии готовности

- [ ] Inventory отражает реально достижимый публичный API всех library targets
  и отличает его от внутренней видимости и generated surface.
- [ ] Каждый публичный API элемент имеет предметное описание; пустые,
  tautological и автоматически сгенерированные boilerplate-комментарии не
  засчитываются.
- [ ] Примеры добавлены к основным сценариям использования и важным контрактам;
  каждый пример проверяем doc-test либо явно помечен как игнорируемый с
  причиной, если выполнение требует внешней среды.
- [ ] Rustdoc warnings/errors устраняются для workspace targets; полнота
  `missing_docs` вводится без скрытия warnings и без отключения lint на crate
  целиком. Если workspace не поддерживает единый lint из-за generated или
  platform-specific surface, это ограничение фиксируется с узкими исключениями.
- [ ] `#[cfg(doc)]` добавлен только при подтверждённой необходимости конкретной
  doc-only декларации; обычная документация не зависит от этого атрибута.
- [ ] CI проверяет `cargo doc` и doc-tests для целевого workspace набора с
  `--locked`; команды и ограничения описаны в канонической документации.
- [ ] API, поведение, зависимости и runtime не менялись ради прохождения
  документационных gates.
