# План 191.2 — отбор инструментов, промпт-профиль и runtime-согласованность

Статус: active implementation contract. Этап следует после overview 191.0 и
предыдущих этапов этого направления.

## Scope и изменяемые контракты

Сделать отбор инструментов предсказуемым для русского и английского запроса и
превратить системный промпт в версионируемый профиль, выводимый из
метаданных каталога.

1. Заменить ASCII-only токенизацию в `adaptive_tool_catalog.rs` на нормализацию,
   покрывающую кириллицу, плюс статический синоним-словарь доменов
   (`файл/read`, `правка/patch`, `поиск/search`, `тест/test`, `сборка/build`,
   `коммит/commit`, `ветка/branch`, `лог/log`). Словарь — данные, не код-условия.
2. Заменить алфавитный fallback на курируемый core-set, ограниченный уже
   авторизованным snapshot: `filesystem.list`, `filesystem.read`,
   `filesystem.search`, `git.status`, `git.diff`, `shell.execute` — те, что
   действительно присутствуют в проекции. Fallback не расширяет authority.
3. Подключить `SelectionCache` к runtime-пути: ключ остаётся производным от
   policy/registry/grant/query, но проекция и хеши манифестов не пересчитываются
   на каждый run. Инвалидация — при изменении регистрации или grant.
4. Вынести сборку системного промпта `core_prelude.rs:651-777` в профиль с
   идентификатором версии. Правила становятся секциями данных; условия
   `has(tool)` заменяются выборкой секции по метаданным каталога из этапа 191.1.
   Профиль передаётся в trace как id и hash. Снимается противоречие «один
   инструмент за ответ» с фактическим fan-out-поведением.
5. Согласовать `catalog_preflight_input`: probe-аргументы обязаны проходить
   `ToolManifest::validate` для заявленных required-полей, иначе безопасный
   инструмент ошибочно выпадает из authorized snapshot.

## Recovery и rollback

Fallback не может вернуть инструмент, отброшенный policy: он работает внутри
уже построенной проекции. Неизвестный или устаревший идентификатор
промпт-профиля даёт детерминированный дефолт, а не пустой промпт. Кэш не хранит
схемы и не переживает изменение grant hash. Rollback: отключение профиля
возвращает текущую сборку промпта и прежний fallback, данные не мигрируют.

## Verification

Unit: русский запрос без ASCII-имён инструментов даёт релевантный набор;
пустой/бессмысленный запрос даёт core-set, а не алфавитный префикс; кэш
инвалидируется при смене policy/grant/registry hash; профиль промпта стабилен
по hash при одинаковых входах; `catalog_preflight_input` проходит валидацию
схемы для всех инструментов. Integration: authorized snapshot остаётся
fail-closed при пустом наборе разрешений.

## Release evidence

Зафиксировать версию профиля промпта и его hash, версию словаря отбора, список
fallback-инструментов, focused test evidence и подтверждение, что fallback не
меняет authority. Плановые проверки не выдавать за выполненные.
