# План 183.1 — Инвентаризация и критерии Rust API

## Изменить

1. Снять baseline workspace packages, library/binary targets, crate roots,
   public re-exports, существующие rustdoc comments/examples и CI-проверки.
2. Построить проверяемую матрицу покрытия по фактически достижимым public items;
   отдельно отметить generated/proc-macro/platform-specific поверхности и
   внутренние `pub`, не являющиеся API потребителей.
3. Зафиксировать единый стандарт комментария: смысл и контракт, параметры и
   результат, ошибки, предусловия/ограничения, cancellation/threading/security
   при применимости; примеры — по ключевым сценариям, не для каждого accessor.
4. Выбрать минимальные пакеты первой волны по повторному использованию и риску;
   не менять API видимость.

## Зависимости

### Блокирующие

- План 183.0: область и определение внешне достижимого API.

### Опциональные

- Уже существующие crate READMEs и design docs как источники точных контрактов.

## Проверка

Сопоставить inventory с `cargo metadata --no-deps`, crate roots/re-exports и
источниками; проверить, что каждый workspace package учтён и никакие
implementation-only items не записаны как внешний контракт.

## Rollback и evidence

Inventory и выбранный порядок остаются в плане, а не превращаются в отдельную
ручную копию документации. Пересмотреть матрицу, если crate roots или target
surface изменились до этапов документирования.
