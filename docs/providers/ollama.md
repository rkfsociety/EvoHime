# Ollama

EvoHime поддерживает Ollama как локальный провайдер. Ключ API не нужен: Core
обращается только к loopback HTTP endpoint, по умолчанию
`http://127.0.0.1:11434/v1`. Удалённые адреса для Ollama отклоняются.

В настройках «Провайдер и модели» можно выбрать Ollama. Core получает
установленные модели через native `GET /api/tags`, показывает их в композиторе
и отдельном блоке настроек, а список моделей для скачивания формирует по
характеристикам устройства: потокам CPU, общей ОЗУ,
свободному месту и максимальной доступной dedicated VRAM. Для интегрированной
графики используется консервативная доля shared video memory. В список
скачивания попадают только модели, для которых одновременно хватает безопасного
запаса ОЗУ и VRAM, а также CPU и свободного места. Если GPU обнаружен, модель не
предлагается при нехватке VRAM даже в случае, когда её теоретически можно было
бы запустить только на CPU: это предотвращает загрузку модели, которая не
соответствует аппаратному профилю устройства.

Если Ollama не найдена, в этом же блоке появляется кнопка «Установить Ollama».
Ева потоково скачивает `OllamaSetup.exe` с официального адреса
`https://ollama.com/download/OllamaSetup.exe`, проверяет допустимый HTTPS-host,
запускает установщик отдельным процессом и после его завершения проверяет
loopback API. Установщик сохраняется только во временный каталог и удаляется
после завершения; произвольный путь или shell-команда из renderer для этого не
используются. Если встроенный Chromium-транспорт блокирует скачивание с
`net::ERR_BLOCKED_BY_CLIENT`, main-процесс повторяет только эту загрузку через
Node HTTPS-транспорт; официальный URL, redirect allowlist, размер и заголовок
Windows-инсталлятора проверяются тем же путём. Отмена/ошибка установки остаётся
видимой в настройках, а уже
установленная Ollama не переустанавливается автоматически.

Скачивание выполняется только через Core-команду `ollama_pull`, с bounded
идентификатором модели и тем же loopback-ограничением. Прогресс native
`POST /api/pull` проходит через Core и публикуется в renderer как bounded
projection: этап, готовый и общий объём и процент, если Ollama их сообщает.
Произвольный native-поток, digest и другие необязательные поля в UI не
передаются; после завершения Core публикует итог операции и обновляет каталог.

Источники API: [Ollama API](https://docs.ollama.com/api), [список локальных
моделей](https://docs.ollama.com/api/tags), [загрузка модели](https://docs.ollama.com/api/pull)
и [OpenAI-совместимый endpoint](https://docs.ollama.com/api/openai-compatibility).
