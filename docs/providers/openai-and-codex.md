# OpenAI API и Codex CLI

EvoHime поддерживает два связанных, но независимых способа работы с OpenAI.

## OpenAI Responses API

В настройках провайдера выберите `OpenAI Responses API`, укажите API-ключ и
модель. По умолчанию используется `https://api.openai.com/v1` и
`gpt-5-codex`. Ключ шифруется Electron `safeStorage`, не попадает в renderer,
логи, SQLite или Git и передаётся Core только через окружение supervisor.

Responses API используется для потокового ответа и function calling. Для новых
Codex-моделей этот маршрут предпочтительнее OpenAI-compatible Chat Completions.

## Codex CLI с входом через ChatGPT

Codex CLI — отдельный локальный coding-исполнитель, а не API-провайдер Core. В
настройках выбери `Движок coding-задач → Codex CLI`, а в поле задачи включи
`Coding-задача (Codex CLI)`. Ева передаст задачу Core, Core запустит
`codex exec --json` непосредственно в выбранном workspace и покажет вывод в
общей ленте. Обычный диалог без этого флажка по-прежнему выполняется Core.

Запуск ограничен выбранным workspace и `workspace-write`; аргументы и окружение
не принимаются от renderer, а API-ключи Евы не передаются дочернему процессу.
Если CLI не установлен, не выполнен вход или завершился с ошибкой, задача
завершается явно — автоматического переключения на другой backend нет.

Нельзя переносить cookies, внутренние токены ChatGPT или содержимое каталога
Codex в настройки EvoHime. ChatGPT-вход остаётся собственностью Codex CLI.

## Биллинг и безопасность

### Состояние Codex в настройках Евы

В разделе `Провайдер и модели` EvoHime подключается к локальному
экспериментальному `codex app-server`, не читая его токены напрямую. Панель
показывает опубликованные Codex модели, позволяет выбрать модель и сохраняет
выбор в `%LOCALAPPDATA%\EvoHime\shell\codex.json`. Если app-server передал окна
лимитов, Ева показывает оставшийся процент и время сброса; при отсутствии этих
данных она сообщает об этом явно.

Для входа используется штатная авторизация Codex CLI через ChatGPT:
`codex login`. Этот канал зависит от установленной версии Codex CLI, поэтому
при обновлении CLI формат данных лимита может измениться.

В панели Евы кнопка `Войти через ChatGPT` открывает отдельное интерактивное
окно Codex CLI с этой командой. После завершения входа нажми `Обновить`:
Ева проверит авторизацию через `codex app-server`, запросив модели и лимиты.
Токены и cookies остаются внутри Codex CLI.

### Установка из Евы

Панель `ChatGPT + Codex` показывает, установлен ли CLI. Если его нет, кнопка
`Установить Codex CLI` запускает Windows Package Manager с точным пакетом
`OpenAI.Codex` и без интерактивного shell. После установки Ева повторно
проверяет `codex app-server`; затем пользователь выполняет `codex login` в
обычном терминале. API-ключ в этой панели не вводится и не хранится.

Настройки API-провайдеров хранятся отдельными профилями в
`shell\provider.json`. Поэтому при переключении между LiteRouter, OpenAI
Compatible и Responses API Ева подставляет их собственные URL, модель, тариф и
признак ключа; ключ другого профиля не передаётся Core.

Подписка ChatGPT и использование OpenAI API являются разными продуктами и
учитываются раздельно. API-ключ никогда не должен находиться в renderer или в
аргументах командной строки.
