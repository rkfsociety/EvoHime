# Plugin marketplace: lock-файл и integrity-проверка

## Цель

Вторая волна `7.102`: локально проверяемая целостность установленных плагинов. Внешней PKI-подписи у OSS-каталогов нет — но EvoHime может зафиксировать, **что именно** было установлено (и с каким trust-уровнем), и в любой момент показать, не изменилось ли это с тех пор. Тихая правка skill-файла установленного плагина перестаёт быть невидимой.

## Выбранный подход

Content-hash вместо git-HEAD: subdir-плагины теряют `.git` при установке, поэтому детерминированный SHA-256 по дереву файлов (отсортированные относительные пути + размер + содержимое; `.git` и симлинки исключены) — единственная честная основа, работающая для всех плагинов одинаково.

Lock-файл `.evohime/plugins.lock.json` в workspace: по одному entry на плагин — `name`, `version`, `source_url`, `ref`, `content_hash`, `trust_level`, `installed_at`. Запись атомарна (tmp + rename). Install/update записывают entry, uninstall удаляет.

## API и статусы

`GET /api/plugins/integrity` для каждого установленного плагина возвращает status:

- `ok` — hash совпадает с lock;
- `modified` — дерево изменилось после установки (правка, инъекция, ручное вмешательство);
- `unlocked` — плагин установлен до появления lock (или каталог подложен вручную) — записи нет;
- `missing` — entry есть, каталога нет (удалён мимо API).

Ответ включает trust-уровень из lock — «чем это было на момент установки», независимо от текущего каталога.

UI: chip состояния целостности у каждого установленного плагина в PluginsPanel.

## Поведение и ошибки

- Проверка только читает файлы; ничего не чинит автоматически — решение (переустановить/удалить) за оператором.
- Повреждённый lock-файл — статус `unlocked` для всех + предупреждение в ответе, не 500.
- Hash считается в `spawn_blocking`; деревья плагинов малы, лимитов не требуется, но симлинки не читаются.
- Lock не содержит секретов и не влияет на runtime-загрузку скиллов.

## Реализационные границы

Вне волны: криптоподписи артефактов и репутация авторов (требуют внешней инфраструктуры, которой у OSS-каталогов нет — фиксируем это как «вне пункта», а не «потом»), автоматический re-install при `modified`, периодический фоновый мониторинг.

## Проверка

- unit-тесты: детерминизм hash (порядок обхода, переименование, правка байта — меняют/не меняют), lock load/save round-trip, повреждённый lock;
- integration: install → entry появился; правка файла → `modified`; uninstall → entry удалён;
- полный Rust workspace test, Clippy, OpenAPI regen, frontend build.

## Критерий готовности

После установки плагина `/api/plugins/integrity` показывает `ok`; правка любого файла плагина переводит его в `modified` с обоими hash в ответе; uninstall очищает lock; PluginsPanel отображает состояние целостности.
