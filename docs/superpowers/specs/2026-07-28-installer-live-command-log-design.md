# Installer Live Command Log Design

**Date:** 2026-07-28  
**Status:** Approved

## Goal

Сделать длительную установку наблюдаемой внутри единственного GUI-окна:

- непрерывно показывать общее время установки и время текущего этапа;
- выводить в «Подробностях» запускаемые внешние команды, их живой вывод,
  результат и длительность;
- описывать внутренние операции Rust понятными записями журнала;
- полностью исключить появление отдельных консольных окон;
- не раскрывать пароли, токены и другие секреты.

## User-visible behavior

Во время установки под названием текущего этапа отображается строка:

```text
Всего 08:42 · этап 03:17
```

Оба значения обновляются, пока установка выполняется. После завершения или
ошибки таймеры фиксируются на итоговом значении.

В журнале сохраняются существующие названия этапов. Для внешней команды
добавляются записи следующего вида:

```text
[12:04:31] > pg_ctl.exe start -D C:\...\data -w -t 30 -l C:\...\postgres.log -o "-p 55432"
[12:04:32] waiting for server to start....
[12:04:34] Команда завершена успешно (2.8 с)
```

`stdout` и `stderr` поступают в журнал во время работы процесса. Для операций,
которые выполняются внутри Rust и не имеют командной строки, журнал сообщает
начало и результат операции: скачивание файла, SHA256-проверка, распаковка,
изменение конфигурации и применение миграций.

## Event model

Фоновая установка передаёт UI структурированные события:

- `Stage` — начался новый пользовательский этап;
- `Operation` — диагностическая запись внутренней операции;
- `CommandStarted` — безопасное отображение запущенной команды;
- `CommandOutput` — строка стандартного вывода или ошибки;
- `CommandFinished` — код/результат и длительность;
- `Error` и `Done` — терминальные состояния.

Получение нового `Stage` сбрасывает только таймер текущего этапа. Время начала
всей установки хранится отдельно. UI уже перерисовывается периодически, поэтому
таймер не требует фонового потока или отдельных timer-событий.

## Command execution

Общий Windows-слой запуска внешних команд должен:

1. устанавливать `CREATE_NO_WINDOW`;
2. перенаправлять `stdout` и `stderr`;
3. читать оба потока без взаимной блокировки;
4. передавать строки вызывающему коду через callback/event sink;
5. возвращать прежний типизированный результат с кодом завершения и ошибкой.

PostgreSQL-команды `initdb` и `pg_ctl` используют этот механизм. Команды
установщика, включая `icacls` и PowerShell для ярлыка, применяют тот же
Windows-флаг и публикуют безопасную командную строку в журнал.

Изменение не открывает полноценный интерактивный терминал: установщику нужен
только потоковый read-only журнал.

## Secret handling

В журнал разрешено выводить только заранее сформированное безопасное
представление команды. Запрещено собирать его непосредственно из полного
`Command` или окружения.

Не выводятся:

- пароль PostgreSQL;
- содержимое временного `pwfile`;
- API-токены и секретные переменные окружения;
- DSN с учётными данными.

Путь к `pwfile` и аргумент `--pwfile` показывать можно, содержимое файла — нет.
Вывод дочернего процесса дополнительно проходит существующую или специально
добавленную минимальную маскировку известных секретов установки.

## Error handling

Если команда завершается с ошибкой, журнал сохраняет:

- безопасную командную строку;
- полученные `stdout/stderr`;
- exit code или ошибку запуска;
- фактическую длительность.

Основное сообщение об ошибке остаётся кратким и пользовательским. Подробности
не теряются и доступны для копирования из журнала.

Таймаут `pg_ctl -t 30` сохраняется. Если запуск PostgreSQL не удался, пользователь
видит, сколько времени занял этап, результат `pg_ctl` и путь к `postgres.log`.

## Testing

Автоматические тесты должны подтвердить:

- формат общего и этапного таймеров, включая значения больше часа;
- сброс этапного времени при `Stage` без сброса общего;
- фиксацию времени после `Done` и `Error`;
- порядок событий запуска, вывода и завершения команды;
- наличие `CREATE_NO_WINDOW` у Windows-команд;
- отсутствие пароля и содержимого `pwfile` в безопасном отображении и журнале;
- сохранение существующей семантики ошибок PostgreSQL.

По требованию пользователя сборка и полный набор тестов выполняются только
GitHub Actions после отдельного разрешения на push. Локально допустимы
форматирование и статическая проверка diff без сборки.

## Scope

В задачу входят таймеры, структурированный живой журнал и скрытый запуск
дочерних консольных программ. Интерактивный ввод команд, отмена установки,
переработка прогресс-бара и изменение 30-секундного таймаута PostgreSQL в эту
задачу не входят.
