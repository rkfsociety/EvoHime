# Browser session: скриншоты и ввод текста

## Цель

Вторая волна `7.100`: замкнуть визуальный цикл агента. Скриншот даёт канал «смотреть» (в т.ч. для будущих мультимодальных моделей), ввод текста — канал «действовать» в формах. Вместе с navigate/click/read первой волны это полный loop смотреть → действовать → смотреть.

## Инструменты

- `browser.session.screenshot {path?, full_page?}` — `Page.captureScreenshot` (PNG) текущей вкладки задачи; файл записывается **внутрь workspace sandbox** (по умолчанию `.evohime/screenshots/<task_id>-<timestamp>.png`), возвращаются путь и размер. Файл виден в Files-панели и доступен `filesystem.read`.
- `browser.session.type {selector, text, settle_ms?}` — фокус на `document.querySelector(selector)`, установка `value` (или `textContent` для contenteditable) и dispatch `input`/`change`, чтобы React/Vue-формы увидели изменение; после — settle и snapshot страницы. Ошибка, если селектор не найден.

Оба — permission `BrowserAccess`, та же persistent-сессия и реестр, что в wave 1.

## Безопасность и лимиты

- Селектор и текст вшиваются в фиксированное JS-выражение как JSON-литералы (как `click` в wave 1) — вырваться в script-контекст нельзя; произвольный eval по-прежнему не вводится.
- Путь скриншота проходит `resolve_for_write` sandbox — записать вне workspace нельзя; расширение принудительно `.png`.
- Размер декодированного скриншота ограничен (16 MiB); превышение — ошибка без записи файла.
- Лимит длины `text` (16 KiB) — инструмент для форм, не для загрузки документов.
- Пароли/секреты в `text` — ответственность вызывающего; инструмент не логирует текст, в structured-результате возвращается только длина.

## Реализационные границы

Вне волны: скриншоты элементов по селектору, эмуляция клавиатуры по-символьно (`Input.dispatchKeyEvent`), передача изображения модели как vision-вход, автозапуск браузера. Ложатся поверх того же клиента.

## Проверка

- mock-CDP тесты без Chrome: `captureScreenshot` возвращает base64-PNG → файл появляется в sandbox; `type` меняет состояние mock-страницы, ошибка на отсутствующем селекторе; отказ на превышении лимитов;
- полный Rust workspace test, Clippy, frontend build.

## Критерий готовности

В одной задаче агент выполняет `navigate → type → click → screenshot`, PNG появляется в workspace, `read` видит введённый текст; text не попадает в логи и structured-результат; mock-тесты проходят без Chrome.
