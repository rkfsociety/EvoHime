# Voice input and TTS design

## Цель

Добавить в browser-only интерфейс EvoHime необязательные голосовой ввод и озвучивание ответов ассистента без изменений backend API, базы данных и протокола WebSocket.

## Область

- Голосовой ввод работает через Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`).
- Язык распознавания по умолчанию — `ru-RU`.
- Промежуточный текст распознавания показывается в существующем поле composer и заменяется финальным результатом.
- Финальный текст остаётся редактируемым и отправляется обычным `user.message`.
- Озвучивание работает через `window.speechSynthesis`.
- У каждого сообщения ассистента появляется действие «Озвучить»; повторное нажатие останавливает текущую речь.
- Во время потокового ответа озвучивание не запускается автоматически и доступно после появления завершённого сообщения.
- Аудио не записывается, не сохраняется и не передаётся на сервер.

## Архитектура

Добавляется изолированный frontend-хук для голосовых возможностей, который:

1. определяет поддержку API без обращения к `window` во время SSR/build;
2. управляет состояниями `idle`, `listening`, `unsupported`, `error`;
3. прокидывает interim/final transcript вызывающему composer;
4. очищает recognition и speech synthesis при размонтировании;
5. гарантирует, что одновременно активен только один recognition и один speech utterance.

`app.tsx` использует хук для кнопки микрофона и передаёт действие озвучивания компоненту сообщения. Существующая отправка сообщения, потоковые события и копирование текста не меняются.

## UX и доступность

- Кнопка микрофона находится в composer рядом с вложениями.
- Во время записи кнопка получает активное визуальное состояние и `aria-pressed="true"`.
- `aria-label` и `title` различают состояния «Начать голосовой ввод», «Остановить голосовой ввод» и «Голосовой ввод недоступен».
- Ошибки разрешения микрофона, отсутствия речи и отказа браузера показываются через существующий `composerNotice` без исключения из React-цикла.
- Кнопка озвучивания имеет `aria-label`, отражающий действие: «Озвучить сообщение» или «Остановить озвучивание».
- Нажатие озвучивания другого сообщения останавливает предыдущую речь.
- На мобильном layout новые touch-targets имеют размер не менее 44px.

## Совместимость и ограничения

- Если распознавание речи не поддерживается, кнопка микрофона disabled и объясняет причину через tooltip/accessible label.
- Если `speechSynthesis` не поддерживается, действие озвучивания не показывается или disabled с тем же принципом fallback.
- Никаких новых npm-зависимостей и серверных переменных не требуется.
- Автоматическое озвучивание ответов, выбор голоса и настройка скорости не входят в этот пункт; их можно добавить отдельно.

## Тестирование

- Unit-тесты хука/адаптеров с mock-объектами Web Speech API: unsupported, start/stop, interim/final transcript, error и cleanup.
- Проверка `npm run typecheck` и `npm run build`.
- Ручная проверка в поддерживаемом Chromium-браузере: разрешение микрофона, отмена записи, редактирование расшифровки, отправка, запуск/остановка TTS и переключение между сообщениями.
- Ручная проверка fallback в браузере без API.

## Критерий готовности

Пользователь может голосом заполнить обычный composer, отредактировать расшифровку и отправить её, а также озвучить любой завершённый ответ ассистента. В неподдерживаемом браузере чат продолжает работать без голосовых функций и без ошибок в консоли.
