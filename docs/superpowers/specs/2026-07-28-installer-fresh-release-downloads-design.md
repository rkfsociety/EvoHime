# Свежая загрузка файлов релиза в установщике

## Цель

Исключить повторное использование архивов, оставшихся от предыдущего запуска
`evohime-setup.exe`. При каждом запуске установщик должен заново скачать все
компоненты текущего последнего релиза и не применять HTTP Range-докачку.

## Область изменения

Изменяется только первоначальная установка в `crates/installer`.
Механизм обновления уже установленной EvoHime в `crates/launcher` сохраняет
существующую проверяемую SHA256 докачку.

Установщик продолжает использовать ссылки вида:

```text
https://github.com/rkfsociety/EvoHime/releases/latest/download/<asset>
```

Фиксация единого тега релиза через GitHub API и изменение состава релизных
артефактов не входят в эту работу.

## Загружаемые файлы

Каждый запуск заново загружает:

- `server.zip`;
- `launcher.zip`;
- `dist.zip`;
- `migrations.zip`;
- `worker.zip`;
- `postgres.zip`;
- соответствующий файл `<asset>.sha256` для каждого архива.

## Поток установки

Для каждого архива установщик выполняет один и тот же последовательный
процесс:

1. Если существуют окончательный файл или `<asset>.part`, удаляет их.
2. Загружает свежий `<asset>.sha256`.
3. Загружает архив целиком в `<asset>.part` обычным GET-запросом без заголовка
   `Range`.
4. Проверяет SHA256 временного файла.
5. При совпадении SHA256 переименовывает `<asset>.part` в окончательное имя.
6. При несовпадении удаляет `.part` и прекращает установку.

Распаковка начинается только после успешной загрузки и проверки всего набора
архивов.

## Очистка незавершённой установки

Если каталог установки существует без `.setup_complete`, его удаление должно
завершиться успешно до продолжения установки. Ошибка `remove_dir_all` больше
не игнорируется: установщик выводит понятную ошибку и останавливается, чтобы
не смешивать старое состояние с новой установкой.

Для завершённой установки весь каталог не удаляется. Перед загрузкой
удаляются только перечисленные архивы и их `.part`, поэтому существующие
данные PostgreSQL не затрагиваются этим шагом.

## Ошибки и целостность

- HTTP-ответ вне диапазона `200..299` считается ошибкой загрузки.
- Отсутствующий старый файл не считается ошибкой; любая другая ошибка его
  удаления или удаления `.part` останавливает установку.
- Несовпадение SHA256 останавливает установку и удаляет повреждённый `.part`.
- Окончательное имя получает только полностью скачанный и проверенный файл.
- При следующем запуске все архивы снова скачиваются с нуля.

Выбранный подход допускает, что GitHub может переключить `latest` на новый
релиз между загрузками отдельных файлов. Это принятый компромисс: каждый
архив проверяется по заново полученному SHA256, но единый тег релиза не
фиксируется.

## Интерфейс общей библиотеки

В `evohime-artifacts` добавляется отдельная операция свежей проверяемой
загрузки без Range-докачки. Установщик использует только её. Существующие
`download_with_resume` и `download_with_resume_and_verify` сохраняются для
лаунчера и не меняют свой контракт.

## Проверка

Автоматические тесты должны подтверждать:

- свежая загрузка не отправляет `Range`, даже если окончательный файл уже
  существует;
- старые окончательный файл и `.part` заменяются содержимым удалённого
  архива;
- окончательный файл появляется только после совпадения SHA256;
- повреждённая загрузка или неверный SHA удаляют `.part` и возвращают ошибку;
- ошибка очистки незавершённой установки не игнорируется;
- существующие тесты докачки лаунчера продолжают проходить.

Обязательные проверки:

```text
cargo fmt --all -- --check
cargo test -p evohime-artifacts
cargo test -p evohime-launcher
cargo test -p evohime-installer --test ui
cargo check -p evohime-installer
```
