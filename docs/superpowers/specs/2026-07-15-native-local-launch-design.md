# Нативный локальный запуск EvoHime — дизайн

## Цель

Запускать EvoHime на Windows нативно: Rust-сервер и Vite frontend работают локальными процессами, PostgreSQL устанавливается и запускается как нативная служба, а backend использует локальный контекст `gh` для GitHub-статуса.

## Архитектура

- `start-dev.ps1` остаётся единым launcher-ом и запускает server/web напрямую.
- PostgreSQL 16 работает локально на `localhost:5432` с базой `evohime`, пользователем `evohime` и паролем `evohime`; при отсутствии прав администратора используется официальный portable-пакет и управляемый локальный процесс.
- Launcher проверяет наличие обязательных инструментов, доступность PostgreSQL и наличие npm-зависимостей до запуска процессов.
- Контейнерный deployment не входит в поддерживаемую архитектуру проекта.
- Существующая команда `/api/auth/github` продолжает выполняться в локальном backend-процессе и видит авторизацию Windows `gh`.

## Изменения

1. Добавить скрипт подготовки локального PostgreSQL: проверка/загрузка portable-пакета, инициализация data directory, запуск процесса, создание роли и базы, применение миграций.
2. Усилить `start-dev.ps1`: использовать подготовку базы, проверять `cargo`, `npm`, `gh` и порты, передавать `.env`-настройки без затирания пользовательского API-ключа.
3. Добавить явные команды `setup:local` и `start:local` либо эквивалентные Windows-обёртки.
4. Обновить README и AGENTS.md с нативным сценарием и удалить контейнерные артефакты.

## Ошибки и безопасность

- Если PostgreSQL недоступен, launcher завершается с точной командой исправления и не запускает полурабочий backend.
- Существующие значения `LITEROUTER_API_KEY` из `.env` не перезаписываются пустой строкой.
- Пароль локальной dev-базы используется только для локального окружения; production deployment не меняется.
- Контейнерные файлы и конфигурация удаляются из проекта.

## Проверка

- Проверить `cargo fmt --all -- --check` и `cargo test --workspace`.
- Проверить frontend build.
- Запустить нативный PostgreSQL и launcher, затем проверить `/health`, `/api/auth/github` и доступность web-панели.
- Убедиться, что `gh api user --jq .login` и значение `login` в `/api/auth/github` совпадают.
