# Надёжное обновление с автоматическим rollback

## Цель

Обновление установленной Евы должно либо завершаться полностью и проверенно, либо автоматически возвращать предыдущую рабочую версию. Это должно работать и после аварийного завершения процесса или внезапного выключения Windows.

## Границы

В релизный артефакт по-прежнему входит один пользовательский установщик `EvoHime-Setup.exe`. Внутренняя логика обновления не создаёт дополнительных ярлыков и не требует административных прав.

## Архитектура

Будет добавлен скрытый компонент `evohime-updater.exe`. Клиент передаёт ему путь к скачанному установщику и каталогу установки, после чего updater работает независимо от закрывающегося UI.

Updater использует каталог транзакции в `%LOCALAPPDATA%\EvoHime\update-state`. До запуска установщика он:

1. создаёт уникальный каталог резервной копии;
2. копирует текущие `EvoHime.exe`, `evohime-core.exe`, `evohime-supervisor.exe` и `evohime.manifest.json`;
3. записывает и сбрасывает на диск журнал с фазой `installing`, каталогом установки и каталогом backup;
4. запускает установщик и ждёт его завершения;
5. проверяет наличие всех компонентов и соответствие версии;
6. при успехе записывает фазу `committed` и удаляет backup;
7. при ненулевом коде, исключении или неполной установке восстанавливает backup и удаляет журнал.

`evohime-supervisor.exe` перед запуском Core проверяет незавершённый журнал. Если фаза не `committed`, supervisor выполняет восстановление из backup, проверяет компоненты и только затем запускает Core. Поэтому авария с потерей updater не оставляет приложение в неопределённом состоянии.

Все записи журнала и замены файлов выполняются через временный файл и атомарное переименование. Backup хранится вне каталога установки, чтобы Inno Setup не мог его затронуть.

## Состояния транзакции

```text
prepared -> installing -> committed
                    \-> rollback-required -> restored
```

`prepared` означает, что backup полностью создан. Любой журнал с `prepared`, `installing` или `rollback-required` считается незавершённым и восстанавливается при следующем запуске. Журнал `committed` удаляется после успешной проверки.

## Безопасность и ограничения

- Путь установки должен быть абсолютным и находиться в разрешённом каталоге EvoHime.
- Backup копируется только из фиксированного списка файлов, без рекурсивного удаления произвольных путей.
- Перед восстановлением updater останавливает запущенные процессы клиента.
- Если backup повреждён или отсутствует, восстановление не выполняется поверх данных; пользователь получает диагностическую ошибку.
- Скачанный установщик по-прежнему проверяется по SHA-256 до создания транзакции.

## Проверка

Обязательные тесты:

- журнал корректно создаётся, сбрасывается, читается и удаляется после commit;
- аварийная фаза восстанавливает все четыре компонента и не трогает посторонние файлы;
- ненулевой код установщика вызывает rollback;
- повторный запуск после оставленного журнала выполняет recovery;
- успешная установка проходит существующий install/upgrade smoke;
- CI собирает и пакует updater только после native CI checks.
