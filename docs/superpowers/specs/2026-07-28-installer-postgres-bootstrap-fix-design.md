# Исправление bootstrap PostgreSQL в установщике

## Цель

Установщик EvoHime должен инициализировать bundled PostgreSQL 16 от имени
обычного текущего пользователя Windows, без запуска с правами администратора,
и показывать читаемую ошибку при сбое PostgreSQL.

## Подтверждённая причина

Перед `initdb` установщик отключает наследование ACL каталога `data` и выдаёт
текущему пользователю `FullControl` только на сам каталог (`USERNAME:F`).
Из-за отсутствия наследуемых ACE созданные `initdb` вложенные каталоги не
получают прав, достаточных для записи, поэтому запись в `base/1`,
`pg_multixact/offsets`, `pg_wal/archive_status` и другие вложенные пути
завершается `Permission denied`.

Поведение воспроизводится bundled `initdb.exe` на чистом временном каталоге.
При праве `USERNAME:(OI)(CI)F` тот же `initdb.exe` завершается успешно.

Вторая проблема — PostgreSQL пишет локализованный `stderr` в системной
Windows-кодировке, а Rust-код безусловно декодирует байты как UTF-8. На русской
локали это превращает текст ошибки в нечитаемые символы.

## Выбранное решение

### ACL

`restrict_to_current_user` продолжает отключать у `data` унаследованные права,
но выдаёт текущему пользователю `FullControl` с наследованием на файлы и
каталоги: `(OI)(CI)F`. Это гарантирует, что все объекты, создаваемые `initdb`
внутри `data`, автоматически наследуют необходимые разрешения.

Это сохраняет закрытый каталог данных и позволяет `initdb` создавать дерево
кластера на любой глубине. Изменение ограничивается функцией
`restrict_to_current_user`; остальная логика установки и настройки PostgreSQL
не меняется. Удалять ACL-ограничение или требовать elevation установщика не
нужно.

### Кодировка вывода PostgreSQL

Общая обёртка `run_pg_tool` запускает PostgreSQL-утилиты с `LC_ALL=C`.
PostgreSQL использует локаль `C`, благодаря чему диагностические сообщения
становятся англоязычными и совместимыми с существующим UTF-8-декодированием.
Это устраняет зависимость текста ошибок от системной ANSI-кодировки Windows.

Переменная окружения устанавливается только для запускаемых PostgreSQL-утилит
и не влияет на локаль установщика, PostgreSQL-сервера после установки или
пользовательской системы.

## Обработка неудачной установки

Исправление не удаляет существующий каталог PostgreSQL автоматически. Удаление
или восстановление частично созданного `data` относится к отдельной политике
повторной установки и не должно без подтверждения затрагивать пользовательские
данные.

Исправление предполагает инициализацию только пустого каталога `data`.
Текущий повреждённый каталог можно удалить вручную только после подтверждения,
что успешного кластера в нём нет.

## Проверка

1. Windows-тест ACL создаёт временный `data`, применяет
   `restrict_to_current_user`, создаёт вложенный каталог и файл внутри него и
   подтверждает успешную запись.
2. Модульный тест построения PostgreSQL-команды подтверждает наличие
   `LC_ALL=C`.
3. `cargo test -p evohime-installer` и `cargo test -p evohime-launcher`
   завершаются без ошибок.
4. Bundled `initdb.exe` успешно создаёт кластер в чистом временном каталоге
   после применения исправленной ACL и завершается с кодом выхода `0`.
5. Преднамеренно ошибочный запуск PostgreSQL возвращает читаемый
   англоязычный текст без mojibake.
6. `cargo fmt --check`, сканирование кодировок и `git diff --check` проходят.

## Вне объёма

- Запуск установщика с повышенными правами.
- Изменение порта, пользователя, пароля или схемы аутентификации PostgreSQL.
- Автоматическое удаление текущего частично созданного каталога `data`.
- Изменение UI установщика, кроме читаемого текста уже существующей ошибки.
