# Eval harness: live-режим и LLM-as-judge

## Цель

Вторая волна `7.101`: те же golden tasks можно прогнать против **реального** провайдера (LiteRouter) и оценить свободный ответ модели судьёй-LLM по rubric. CI остаётся детерминированным (mock-режим); live-режим — явный opt-in для ночных/ручных regression-прогонов.

## Выбранный подход

Harness обобщается: `run_golden_task_with_gateway(task, gateway, judge)` принимает любой `ModelGateway`. Mock-режим (существующий) строит scripted-провайдер из `script`; live-режим берёт `ModelGateway::try_from_env()` — модель сама решает, какие инструменты вызывать, `script` игнорируется, детерминированные `expect` проверяются как раньше.

Judge — второй вызов той же модели: финальный ответ агента + `rubric` задачи → строгий JSON-вердикт `{"pass": bool, "score": 0-10, "reason": "..."}`. Парсинг вердикта устойчив к обёрткам (извлекается первый JSON-объект из текста); непарсибельный вердикт — это провал задачи, а не тихий pass.

## Формат

Golden task получает опциональное поле `rubric` — критерии оценки свободного ответа. В mock-режиме `rubric` игнорируется (ответ и так фиксирован сценарием). Задача без `rubric` в live-режиме проверяется только детерминированными `expect`.

## CLI

`evohime-eval --live [--judge]`:

- `--live` — гоняет задачи против `ModelGateway::try_from_env()`; без сконфигурированного провайдера — понятная ошибка и ненулевой код;
- `--judge` — дополнительно судит задачи с `rubric`; вердикт с `pass: false` делает задачу проваленной, `score`/`reason` печатаются в отчёте;
- без флагов поведение прежнее (mock, детерминизм).

Интеграционный тест CI не трогает live-режим: он всегда использует mock. Live-путь покрыт тестами через инъекцию mock-gateway в ту же обобщённую функцию.

## Поведение и ошибки

- Live-прогон недетерминирован по построению — отчёт это отражает: провал live-задачи означает «модель+система не справились с задачей», а не обязательно регрессию кода.
- Judge не получает системный доступ: только текст задачи, ответа и rubric.
- Ошибка провайдера (сеть, ключ) — провал задачи с сообщением, усечённым без утечки ключей.
- Таймаут агент-цикла обеспечивается существующими bounded limits agent loop.

## Реализационные границы

Вне волны: параллельный прогон live-задач, история результатов в PostgreSQL, сравнение нескольких провайдеров бок-о-бок, UI-панель. Формат вердикта рассчитан на расширение.

## Проверка

- unit-тесты: парсинг вердикта (чистый JSON, JSON в обёртке, мусор → ошибка), сборка judge-промпта;
- интеграционные: live-путь с mock-gateway (scripted ответ проходит `expect`; judge с mock-вердиктом `pass:false` проваливает задачу);
- полный Rust workspace test, Clippy, frontend build.

## Критерий готовности

`cargo run -p evohime-evals --bin evohime-eval -- --live --judge` при настроенном LiteRouter гоняет golden tasks против живой модели, судит задачи с `rubric` и возвращает ненулевой код при провале; CI-режим не изменился и остаётся детерминированным.
