# Backup/export: sessions + memory

## Цель

Добавить локальный CLI-экспорт, который создаёт переносимый JSON-дамп сессий и структурированной памяти EvoHime для резервного копирования и миграции оператора.

## Объём

Экспорт включает:

- метаданные формата (`format`, `version`, `exported_at`);
- активные и архивные сессии;
- сообщения каждой сессии;
- задачи, шаги и события каждой сессии;
- все структурированные `memory_items` в переносимом представлении.

Legacy-таблицы `session_memory` и `global_memory` отдельно не экспортируются: они являются migrate-only источником и не должны создавать дубликаты относительно `memory_items`.

## Архитектура

В `crates/storage/src/backup.rs` появятся сериализуемые DTO дампа и функция сборки `BackupDump` из `PgPool`. Она использует существующие storage-запросы и модели, поэтому CLI не дублирует SQL и остаётся согласованным с runtime.

В storage-пакете появится бинарник `evohime-export`. Он принимает `--output <path>` и подключается к `DATABASE_URL` через существующий pool-конфиг. Экспорт сначала сериализуется в память, записывается во временный файл рядом с назначением и затем атомарно переименовывается в итоговый путь. Ошибка не должна оставлять частичный backup.

Формат первой версии — JSON UTF-8. Структура рассчитана на последующее добавление импортёра и расширение формата через увеличение `version`, без изменения смысла уже существующих полей.

## Безопасность и ошибки

- CLI не принимает произвольный SQL и не изменяет базу данных.
- Путь назначения создаётся только как файл; родительский каталог должен существовать.
- Существующий файл заменяется только после успешной сериализации и полной записи временного файла.
- Ошибки подключения, чтения, сериализации и переименования завершают CLI с ненулевым кодом и понятным сообщением.
- Экспорт сохраняет пользовательские сообщения и memory content как данные backup; CLI не выводит содержимое дампа в терминал.

## Проверка

- unit-тесты проверяют версию/формат, сериализацию пустого дампа и стабильную структуру DTO;
- storage integration-тест проверяет, что сборщик получает сессию, связанные сообщения/задачи/шаги/события и memory items;
- CLI smoke-проверка подтверждает создание JSON-файла через `--output`;
- полный Rust workspace test, Clippy и frontend typecheck/build остаются зелёными.

## Критерий готовности

Команда

```text
cargo run -p evohime-storage --bin evohime-export -- --output backup.json
```

создаёт валидный JSON backup, который содержит сессии и `memory_items`, не меняет БД и не оставляет временный файл после успешного завершения.
