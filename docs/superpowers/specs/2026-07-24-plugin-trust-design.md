# Plugin marketplace: trust scores и risk scan

## Цель

Начать `7.102`: marketplace (каталог + install/update/uninstall) уже существует, но все плагины выглядят одинаково доверенными. Волна добавляет честную оценку доверия каждому элементу каталога и статическую проверку рисков при установке — чтобы «случайный репозиторий с curl|bash в хуке» не устанавливался молча.

## Выбранный подход

Trust score считается **только из проверяемых сигналов**, без самодекларируемых рейтингов и внешних сервисов:

- ярус источника каталога: официальный Anthropic marketplace → «official»; источники из `DEFAULT_CATALOG_SOURCES` → «curated»; пользовательский источник (env/настройки) → «community»;
- пиновка версии: 40-hex commit ref > именованный tag/branch > отсутствие ref;
- HTTPS git-URL и полнота метаданных (описание, версия).

Сумма сигналов → score 0–100 и уровень `official` / `curated` / `community` / `unverified` с человекочитаемыми `reasons`. Никакой сетевой активности сверх уже существующей загрузки каталога.

Risk scan — статический проход по файлам склонированного плагина **до** финализации установки: bounded по числу/размеру файлов, ищет опасные паттерны (`curl|sh`-пайпы, `rm -rf /`, base64-декод в shell, PowerShell `-EncodedCommand`/`IEX`, обращения к `EVOHIME_*`/`LITEROUTER_API_KEY`), плюс наличие исполняемых бинарей. Находки — `{file, pattern, excerpt}`.

## Поведение установки

- Находки риска у плагина уровня ниже `official` → установка отклоняется, каталог findings возвращается в ошибке; клон удаляется.
- `force: true` в запросе устанавливает несмотря на находки; findings всё равно возвращаются в ответе установки.
- Плагин `official`-уровня с находками устанавливается, но findings возвращаются (официальность не отменяет информирование).
- Scan не выполняет код плагина и не следует симлинкам.

## API и UI

- `CatalogPlugin` дополняется `trust: { score, level, reasons }`.
- `InstalledPlugin` дополняется `risk_findings` (пустой массив — норма).
- `InstallPluginRequest` получает опциональный `force`.
- PluginsPanel показывает trust-бейдж (уровень + score) в каталоге; ошибка установки с findings отображается существующим механизмом ошибок. Отдельный force-UI не вводится в этой волне — force доступен через API сознательно.

## Реализационные границы

Вне волны: репутация авторов, подписи артефактов, community-рейтинги, автоматическое обновление score после установки, sandbox-исполнение плагинов. `Trust` рассчитан на добавление сигналов без ломки формата.

## Проверка

- unit-тесты: ярусы источников, пиновка ref, уровни score; risk scan на синтетическом дереве (позитив/негатив, лимиты, бинарь);
- install-тест: mock-каталог + локальный репозиторий с рискованным файлом → отказ без force, установка с force, findings в ответе;
- полный Rust workspace test, Clippy, frontend typecheck/build.

## Критерий готовности

Каталог отдаёт trust для каждого плагина; плагин из пользовательского источника с `curl | sh` в скрипте не устанавливается без `force`, а причина отказа перечисляет файлы и паттерны; официальные плагины сохраняют прежний UX; PluginsPanel показывает уровень доверия.
