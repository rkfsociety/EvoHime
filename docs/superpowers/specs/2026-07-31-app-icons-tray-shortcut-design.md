# Design: брендированные иконки для установленной версии EvoHime

Дата: 2026-07-31

## Контекст

EvoHime — веб-панель (browser only, без Electron). Но для локальной установки уже
существует полноценный конвейер (реализован ранее, до этой сессии):

- `crates/launcher` — трей-приложение (`evohime-launcher.exe`), запускается из
  автозагрузки, поднимает `server` + Python `worker` как дочерние процессы,
  показывает статус через `tray_icon` крейт.
- `crates/installer` — `evohime-setup.exe`, ставит Postgres (портативный,
  `postgres.zip`), применяет миграции, создаёт `.lnk`-ярлык
  (`crates/installer/src/shortcut.rs`), запускает launcher.
- `crates/updater` — самообновление, статически слинкован.
- `.github/workflows/build-releases.yml` — единый релизный конвейер, публикует
  `evohime-setup.exe` + zip-артефакты на GitHub Releases по семверу
  `v0.0.NNNNNN`.

Установленная (релизная) версия — то, чем пользователь реально пользуется; dev
(`start-dev.ps1`) — только для тестирования до релиза.

## Проблема

Ни одна точка входа сейчас не показывает бренд:

1. **exe-иконка отсутствует.** У `launcher`, `installer`, `updater`, `server`
   нет `build.rs` — иконка не встроена в PE-ресурсы. Explorer/таскбар/UAC-диалог
   показывают дефолтную серую иконку Rust-бинарника.
2. **Трей-иконка — не иконка, а квадрат.** `crates/launcher/src/main.rs:948`
   (`status_icon`) рисует сплошной цветной квадрат 16×16 в памяти
   (`[0,200,0,255]` / `[200,0,0,255]`), без картинки вообще.
3. **Ярлык наследует иконку exe** (`shortcut.rs` не указывает `IconLocation`) —
   значит проблема 1 автоматически чинит и ярлык, отдельно ничего делать не
   надо.
4. Веб-фавиконка формально есть (`frontend/web/public/favicon.ico`,
   `favicon.svg`), но не проверена на актуальность относительно канона.

## Находка: канон уже существует

`frontend/web/public/brand/` содержит утверждённый образ EvoHime — не нужно
рисовать нового персонажа:

- `agent-avatar.png` / `agent-avatar-{64,128,256}.webp` — портрет: серебристо-
  белые длинные волосы, бирюзовые (`#3ed7b2`-ish) глаза, тёмная техно-одежда,
  тёмный фон.
- `agent-mark.svg` (32×32, `viewBox="0 0 32 32"`) — уже упрощённая
  иконка-логотип этого же персонажа: скруглённый тёмный фон `#0b111f`,
  силуэт волос, лицо, бирюзовые блики в глазах, лёгкая улыбка/смирк.
  Коммит `fc6dd6a "feat: add EvoHime SVG mark and favicon"`.
- `favicon.svg` — идентичен `agent-mark.svg` (уже используется как фавиконка
  веб-панели).

**Решение: `agent-mark.svg` — единственный источник для всех иконок ниже.**
Это гарантирует визуальную согласованность с уже существующим брендом продукта
и не требует нового арта. Он векторный — рендерится в любой размер без потери
чёткости, что как раз то, что нужно для набора 16/32/48/128/256.

## Дизайн

### 1. Растеризация `agent-mark.svg` → набор PNG → `.ico`

Пайплайн (Rust, чтобы не тащить Node/Python зависимость в релизный конвейер):
маленький bin-target (например `xtask` или `crates/installer/src/bin/gen-icons.rs`,
запускается вручную разработчиком, не на CI) на `resvg` + `usvg` + `tiny-skia`
(чистый Rust, без системных зависимостей типа Inkscape/ImageMagick):

1. Рендерит `agent-mark.svg` в PNG на размерах 16/32/48/128/256 px.
2. Собирает multi-res `.ico` (формат ICONDIR с PNG-фреймами — поддерживается
   Windows Vista+) → `assets/branding/evohime.ico`.
3. Копирует PNG 32×32 → `frontend/web/public/favicon.ico`-эквивалент (или
   оставляет `favicon.svg` как есть, раз он уже идентичен канону — фавиконку
   трогать не нужно, она уже правильная).

Результат коммитится в репозиторий (`assets/branding/evohime.ico` и
промежуточные PNG) — не генерируется на CI при каждой сборке, чтобы не тащить
новую тулу в релизный workflow.

### 2. Встраивание иконки в exe

Добавить `build.rs` + `winres` (Windows-only build-dependency, стандартный
способ встраивания `.ico` в PE-ресурсы через `windres`/`rc.exe`) в четыре
крейта: `launcher`, `installer`, `updater`, `server`. Каждый `build.rs`
подключает один и тот же `assets/branding/evohime.ico`. Даёт брендированную
иконку в Explorer, таскбаре, диалоге UAC, и (за счёт п.3 ниже) в ярлыке — без
изменений в `shortcut.rs`.

### 3. Трей-иконка

Заменить `status_icon()` в `crates/launcher/src/main.rs`: вместо закрашенного
квадрата — `include_bytes!` PNG 32×32 (из того же `agent-mark.svg`-рендера),
декодировать в RGBA (крейт `image`, уже вероятно в дереве зависимостей —
проверить при реализации), передать в `tray_icon::Icon::from_rgba`. Индикатор
здоровья (healthy/unhealthy) — небольшая цветная точка-бейдж, наложенная поверх
иконки в углу (зелёная/красная), а не смена всей иконки на цвет.

### 4. Ярлык

Без изменений в коде: `shortcut.rs` не указывает `IconLocation`, значит
Windows берёт иконку из целевого `evohime-launcher.exe` — она появится
автоматически после п.2.

### 5. Веб-фавиконка

`favicon.svg` уже = `agent-mark.svg` (канон подтверждён, коммит `fc6dd6a`).
Действие не требуется, кроме проверки, что `favicon.ico`
(растровый fallback для браузеров без поддержки SVG-фавиконок) тоже
сгенерирован из актуального канона, а не устарел — сравнить визуально при
реализации и перегенерировать при необходимости через тот же `gen-icons`
инструмент из п.1.

## Вне рамок

- Новый арт персонажа — не нужен, есть канон.
- Тема/анимация трея (несколько кадров) — не запрашивалось, просто
  статичная иконка + цветной бейдж статуса.
- Изменение самого архитектурного решения "browser only" — не трогаем,
  installer/launcher уже существуют и не меняют эту модель (сервер работает
  в фоне, панель открывается в браузере).

## Открытые вопросы для плана реализации

- Куда именно класть `gen-icons` bin (свой мини-крейт `xtask` vs bin внутри
  `installer`) — решить в `writing-plans` с учётом текущей структуры
  workspace `Cargo.toml`.
- Нужна ли иконка серверу (`evohime-server.exe`) вообще, если он не имеет
  видимого UI и запускается как дочерний процесс без своего окна/ярлыка —
  проверить, действительно ли его иконка где-то видна пользователю
  (например, в диспетчере задач она видна), прежде чем решать, включать ли
  его в список из п.2.
