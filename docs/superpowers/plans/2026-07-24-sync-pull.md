# Cloud sync pull Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Третья волна `7.99`: `POST /api/sync/pull` скачивает `BackupDump` с `EVOHIME_SYNC_URL` и восстанавливает его через `restore_backup`; `sync_runs` различает push/pull.

**Architecture:** Миграция добавляет `direction` в `sync_runs`; storage-функции принимают направление. Server pull-handler переиспользует `SyncConfig`, no-redirect клиент и `restore_backup`; тело ответа ограничено 64 MiB и сверяется с checksum-заголовком remote, если тот прислан.

**Tech Stack:** Rust/Axum, SQLx migration, reqwest, существующие `restore_backup`/`RestoreReport`.

## Global Constraints

- Не создавать новую ветку; работать в текущей `main`.
- Токен и тело remote-ответа не попадают в логи/ошибки; лимит 64 MiB жёсткий.
- Один активный run на оператора независимо от направления.
- Push не выполнять без прямого запроса пользователя; после каждой законченной задачи создавать коммит.
